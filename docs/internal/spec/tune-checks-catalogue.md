# Τι μπορεί να ελέγξει το tune — κατάλογος

**Τι είναι αυτό το αρχείο:** κατάλογος δυνατοτήτων. Τι **μπορεί** να ελέγξει
το tune, από πού παίρνει την πληροφορία, και τι αποτελέσματα μπορεί να βγάλει.
Δεν περιέχει αποφάσεις και δεν προτείνει τι θα κάνει καμία εντολή.

Κάθε έλεγχος μπορεί να καταλήξει σε ένα από τρία:

* **γράφει** — το patch προχωράει
* **δεν γράφει** — σταματάει, 0 bytes
* **αναφέρει** — γράφει την πληροφορία και δεν επηρεάζει την απόφαση

---

## Α. Έλεγχοι πάνω στο ίδιο το recipe

| # | Έλεγχος | Από πού το ξέρει | Τι μπορεί να βγει |
|---|---|---|---|
| Α1 | Είναι αρχείο recipe (και όχι π.χ. JSON του identify) | πεδίο `type` | περνά / δεν περνά |
| Α2 | Έχει δηλωμένη έκδοση σχήματος | `schema_version` | περνά / δεν περνά |
| Α3 | Η έκδοση είναι αναγνωρίσιμη (4.x, 5.x, ή νεότερη) | `schema_version` | περνά / δεν περνά |
| Α4 | Υπάρχουν τμήματα ή πεδία που δεν ξέρουμε | σύγκριση με λίστα γνωστών | περνά / δεν περνά |
| Α5 | Το contract συμφωνεί με τα περιεχόμενα (5.0) | επαναϋπολογισμός από τα instructions | περνά / δεν περνά |
| Α6 | Υπάρχει η σφραγίδα `same_file_only` | `metadata.portability` | υπάρχει / δεν υπάρχει |
| Α7 | Πόσες αλλαγές και πόσα bytes δηλώνει | `instructions`, `statistics` | πληροφορία |
| Α8 | Πόσες αλλαγές είναι εκτός calibration (5.0) | τμήμα `regions` | πληροφορία |
| Α11 | Ποιος το έφτιαξε και με ποια εντολή | `producer` (5.0) | πληροφορία |
| Α12 | Αν κάθε instruction κουβαλά τα πεδία που χρειάζεται ο έλεγχος | `ctx_unique`, `ctx`, `context_after` | περνά / δεν περνά |

## Β. Έλεγχοι πάνω στο target

| # | Έλεγχος | Από πού το ξέρει | Τι μπορεί να βγει |
|---|---|---|---|
| Β1 | Μέγεθος αρχείου | μέτρηση | περνά / δεν περνά |
| Β2 | Αν αναγνωρίζεται το binary | identify | ναι / όχι |
| Β3 | Ποια είναι η ταυτότητά του (`match_key`) | identify | τιμή ή καμία |
| Β4 | Τα υπόλοιπα στοιχεία ταυτότητας (κατασκευαστής, οικογένεια, SW version, part number) | identify | τιμές |
| Β5 | SHA-256 του αρχείου | hashing | τιμή |
| Β6 | Αν ικανοποιεί κάποιο γνωστό σχήμα checksum ως έχει | detector pass πάνω στο **αποτέλεσμα** (`health.check_checksums`) — όχι το sweep | ok / fail / skip (κανένα γνωστό σχήμα) · **ποτέ δεν μπλοκάρει** και ποτέ δεν διορθώνει |
| Β7 | Τι bytes έχει στις θέσεις που λέει το recipe | ανάγνωση | ίδια / άλλα |
| Β8 | Πόσες φορές εμφανίζεται ένα μοτίβο μέσα σε παράθυρο | αναζήτηση | αριθμός |

## Γ. Έλεγχοι recipe κόντρα στο target

| # | Έλεγχος | Από πού το ξέρει | Τι μπορεί να βγει |
|---|---|---|---|
| Γ1 | Το μέγεθος ταιριάζει με το δηλωμένο | σύγκριση | περνά / δεν περνά |
| Γ2 | Το `match_key` είναι ίδιο | σύγκριση | ίδιο / διαφορετικό / άγνωστο |
| Γ3 | Το SHA-256 είναι ίδιο με της πηγής | σύγκριση | ίδιο / διαφορετικό |
| Γ4 | Τα `ob` είναι στη δηλωμένη θέση | ανάγνωση | όλα / μερικά / κανένα |
| Γ5 | Αν είναι ήδη πατσαρισμένο (τα bytes εκεί είναι τα `mb`) | ανάγνωση | ναι / όχι |
| Γ6 | Αν το anchor βρίσκεται στο ±2048 | αναζήτηση | βρέθηκε / δεν βρέθηκε |
| Γ7 | Σε ποια θέση βρέθηκε (μετατόπιση από την αναμενόμενη) | αναζήτηση | 0 / θετική / αρνητική |
| Γ8 | Πόσα αντίτυπα του anchor υπάρχουν στο παράθυρο | αναζήτηση | αριθμός |
| Γ9 | Πόσες instructions πέρασαν κάθε έλεγχο | άθροισμα | αριθμοί |

| # | Έλεγχος | Από πού το ξέρει | Τι μπορεί να βγει |

## Ε. Τι δεν μπορεί να κάνει το tune — λείπει η πληροφορία

| # | Τι | Γιατί |
|---|---|---|
| Ε1 | Να ξαναϋπολογίσει fingerprint ή diff | θέλει και το stock binary, όχι μόνο τον στόχο |
| Ε2 | Να ξανατρέξει τον volatile classifier | θέλει το stock — και η v1 του cook δεν τον τρέχει καθόλου |
| Ε3 | Να εντοπίσει checksum stores από την αρχή | θέλει το stock — και **δεν** αποθηκεύονται στο recipe |
| Ε4 | Να διορθώσει checksums | δεν υπάρχει repair πουθενά σήμερα |
| Ε5 | Να αποδείξει ότι ο εγκέφαλος θα δεχτεί το αποτέλεσμα | θέλει δοκιμή στο όχημα |
| Ε6 | Να αποδείξει ότι το tune είναι μηχανολογικά σωστό | θέλει γνώση και μέτρηση πέρα από το αρχείο |

## Παράρτημα — μετρήσεις που αφορούν τους ελέγχους

| Μέτρηση | Τιμή |
|---|---|
| χρόνος identify σε 4 MB | ~768 ms |
| χρόνος SHA-256 σε 4 MB | 2,3 ms |
| χρόνος volatile classifier σε 4 MB | ~197 ms |
| πραγματικό ζεύγος `tests/data/tune/` (EDC17C66) | 79 instructions, 0 μη-μοναδικά anchors, όλα μετατόπιση 0, 41 CODE_AREA (μετά τον καθαρισμό θορύβου), 40/79 εκτός maps |
| αλλαγή σε κενή flash EDC16 (0x30000) | 1 instruction, 4097 αντίτυπα στο παράθυρο |
| EDC16 vs SIMOS 2441 (ίδιο μέγεθος 262.144 B) | 36% ίδια bytes, 82.052 B συνεχές ταυτόσημο |
| checksums στο EDC17C66 ζεύγος | 0 σχήματα επαληθεύονται σε stock και tuned — γι' αυτό το apply δίνει `skip`, όχι «ok» |
| κόστος του disclosure στο apply | +73 ms σε 4 MB (888 ms αντί 815 ms) — detector pass, όχι sweep (965 ms) |
| cross-revision EDC17C60 | 30/49 instructions επιβιώνουν της αναζήτησης anchor |
