## Post-audit resolution (2026-09-06) - pre-release

1. ✅ **Item 4 — `docs/internal/integration.md` deleted.** The stale doc (its
   deprecation banner promised a replacement API "when the time comes" — that
   time was 0.7.6 — and its body still documented the removed
   `openremap-server` daemon) is gone. Reference sweep: nothing live links to
   it (only a historical 0.4.3 changelog row and this audit mention it).
2. ✅ **Item 6 — resolved: no THIRD_PARTY.md row.**
   The tool was used only as a dev-machine oracle to compare our logic
   against an established implementation.
3. ✅ **Item 7 — a malformed user workflow can no longer crash
   `import openremap.api`.** `openremap/api/workflows/__init__.py` gained
   `_load_directory(directory, *, fail_fast)`: the built-in dir still fails
   fast (a broken shipped workflow is a bug), while user-supplied dirs
   (`load_workflows(dir)` and `OPENREMAP_WORKFLOW_DIRS`) skip malformed or
   invalid `.toml` files with a `UserWarning` and keep loading the rest. The
   two guardrail tests in `tests/api/test_workflows.py` now assert
   skip-with-warning + not-registered, and a new `TestUserDirTolerance` class
   covers malformed-skip, good-sibling-loads, the env-dir path, and built-in
   fail-fast. The module docstring and the `changelog/0.7.6.md` workflow
   bullet document the semantics.

Verification: `tests/api/` → **29 passed**; live subprocess repro of the
item-7 scenario (bad `.toml` behind `OPENREMAP_WORKFLOW_DIRS`, fresh
`import openremap.api`) → import OK, the warning names the skipped file, good
siblings and built-ins register, the bad file does not. `test_gs20_extractor.py`
→ **23 passed** (a docstring-only change; no detection logic touched).
