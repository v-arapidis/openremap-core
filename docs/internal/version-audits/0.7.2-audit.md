## Remaining (non-blocking)

1. **0.7.1 changelog entry still says "unreleased"** in `CHANGELOG.md` and
   `changelog/0.7.1.md` while 0.7.2 is dated.  Since 0.7.1 was never pushed,
   decide at release time whether to fold its bullets into 0.7.2 or date it
   separately — otherwise the index shows "0.7.2 (dated)" above "0.7.1
   (unreleased)".
2. **`analyze` health section re-scans internally** — the health verdict runs
   its own identity/checksums/map-count scan rather than reusing `analyze`'s
   already-computed results.  Documented in `analyze.py` as "accepted for v1";
   ~duplicate of the map/checksum work on large files.
3. **TUI `decode_image` error surface** — in the TUI panels a manually-picked
   corrupt HEX/SREC file raises `ValueError`, caught by the generic
   `except Exception` and shown as "Unexpected error" rather than a friendly
   decode message.  No crash; cosmetic.
4. **pyo3 0.25 advisory** remains open (unchanged from 0.7.1) — per AGENTS.md,
   not exploitable in this crate and not release-blocking; remediation
   (`pyo3 ≥ 0.29`) still planned for 0.7.x.
5. **Cross-platform compile claims not independently re-verified here** — the
   changelog reports `maturin --zig` musllinux and `cargo check --target
   x86_64-pc-windows-gnu` / `aarch64-apple-darwin` pass; this session had no
   cross toolchains to re-confirm.  The four new pure-python/compiled
   dependencies all ship universal/prebuilt wheels, so no target compilation
   is required at install time.
