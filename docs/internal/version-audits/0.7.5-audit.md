## Remaining (non-blocking, pre-tag)

   `Cargo.toml`, `Cargo.lock` all still say **0.7.4**. Bump all five at
   release cut (the 0.7.3 lesson: the Cargo pair is easy to forget).
2. **THIRD_PARTY.md credits missing** — `mcs51.rs` names at51 +
   `mmastrac/i8051` (both MIT, oracle-only) and `mcs96.rs` derives its size
   table from MAME `mcs96ops.lst` (BSD-3, oracle-only); all three say "see
   THIRD_PARTY.md" but no entries exist there. Per the house rule
   (community-sourced algorithms get a credit) this should land before the
   tag.
3. **Changelog inaccuracies** — (a) `routine` "covers … 8051 and MCS-96":
   it errors on them today (see table); reword to the shipped surface or
   wire the renderers; (b) the "312,202 boundaries" figure lacks a
   reproducible file set.
4. **`notes/` referenced from committed files** — `changelog/0.7.5.md`
   cites `notes/arch/census.md` and `summary/commands/routine.md` cites
   `notes/0.8.x/todo.md`; `notes/` is gitignored and must not be referenced
   from committed docs (fresh clones have neither file). Reword both.
5. **`_scratch/` is untracked and not gitignored** — the oracle harnesses
   (at51 clone, Ghidra verify scripts, MAME list) would pollute `git
   status`; add to `.gitignore` or exclude before commit.
6. **Wiki gaps (docs repo)** — no `commands/routine/` two-tier entry yet,
   and the decoders concept page still describes only C166/TriCore/SuperH
   (no 8051/MCS-96/M680X/68K/PPC). Per the housekeeping rule both belong
   with this release.
7. **Stale comments** — `_ARCH_TABLE` Simtec56 "(unmapped — no 8051
   decoder yet)"; `pseudocode.py` docstrings + the `arch=None` hint line
   list only c166/tricore/sh/x86 (m680x/m68k/ppc shipped without being
   added to them).
