## Version & packaging

- `0.7.0 → 0.7.1` bumped consistently in `openremap/__init__.py`,
  `pyproject.toml`, `_rs/Cargo.toml`, `_rs/Cargo.lock`, `uv.lock`.
- Note: `Cargo.toml` / `Cargo.lock` / `uv.lock` were **stale at 0.6.4** (the
  0.7.0 release never bumped them) — this changeset catches them up to 0.7.1.
- **pyo3 still `0.25`** — the [GHSA-36hh-v3qg-5jq4] /
  RUSTSEC-2026-0176 advisory is **not** remediated here.  Consistent with
  AGENTS.md: not exploitable in our crate (primitive-only `#[pyfunction]`s),
  not release-blocking; remediation (`pyo3 ≥ 0.29`) planned for 0.7.x.

## Remaining (non-blocking, by design)

1. **No `--no-region-tags` opt-out** — `--no-annotate-maps` still pays ~3 s
   for advisory tags (documented honestly in the changelog).
2. **ISSUE-2 not exercised by the real corpus** — the 4 MB EDC17 pair has
   all-unique anchors (no stamp); verified via synthetic fixtures only
   (`tests/cli/test_cli_same_file_only.py`).  The ~25% of real tunes with
   non-unique anchors aren't in `tests/data/tune/`.
3. **`validate before --json` emits a "Validating …" banner on stdout**
   before the JSON object — breaks strict `stdout | jq` piping.  **Pre-existing**
   (not introduced by 0.7.1); the new test works around it via
   `_parse_json_from_stdout`.
4. **pyo3 advisory** remains open (see above) — planned, not release-blocking.
