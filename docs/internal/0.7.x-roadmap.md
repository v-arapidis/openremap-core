# 0.7.x Roadmap

**Scope:** the 0.7.x stabilization cycle that follows the 0.7.0 milestone
release (2026-08-23).  This is **not** a feature cycle — 0.7.x exists to
make 0.7.0 solid in real use and to fold in proven open-source work.

## Goals

### 1. Refine bugs surfaced by the 0.7.0 release

0.7.0 shipped a lot of surface (cook-volatile, schema 4.5, volatile-aware
audit, six checksum families, Subaru support, Rust migrations, domain
restructure).  Real-world use will find the rough edges — 0.7.x is where
they get fixed:

- bugs reported by users / CI on the 0.7.0 feature set
- correctness hardening of the new paths (volatile classifier, audit
  re-verify, checksum detectors, cook-volatile CLI)
- performance regressions that only show up on real corpora
- doc/UX mismatches discovered through use

**Policy:** fix, don't expand.  A genuine bug fix is always welcome in
0.7.x; a new feature waits for 0.8.0 unless the operator says otherwise.

### 2. Integrate third-party open-source libraries — port, never copy-paste

Where a proven open-source library (or algorithm) covers a gap, integrate
it — with the project's standing policy (`THIRD_PARTY.md`):

- **port algorithms, don't copy code wholesale** — reimplement in the
  OpenRemap codebase (Python or Rust) so the result fits the existing
  service layer and test suite
- **credit the source** — every community-sourced algorithm gets its
  `THIRD_PARTY.md` row (project, what we took, license, where it lands)
- **respect licenses** — GPL/community sources inform the algorithm; the
  OpenRemap codebase stays MIT
- **validate, don't trust** — every port lands with parity tests against
  the reference behaviour, validated on `tests/data/` + synthetic
  fixtures (project constraint: no magic files)

Candidate directions (to be decided with the operator, in no order):
decompiler/RE tooling integration (**in progress** — the capstone
code-reference (xref) signal shipped in 0.7.3: `analyze` + `scan-maps
--xrefs`; the developer-facing disassembler surface is parked in
`notes/roadmap/ideas.md`), A2L/DAMOS parsing, additional
checksum or map-pattern sources, hardware-architecture helpers.

## What 0.7.x is NOT

- not a new-feature release (that's 0.8.0)
- not a TUI rework (the TUI stays stale — CLI is the focus; the modern
  TUI is the **0.9.0** milestone)
- not a schema bump (recipe schema stays 4.5 unless a bug demands it)

## Exit criteria for 0.7.x

- 0.7.0 release-reported bugs triaged: fixed or explicitly deferred with
  a reason
- every third-party integration merged with `THIRD_PARTY.md` credit and
  parity tests green
- full test suite green; docs consistent (link sweep clean)
